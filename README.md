# Midjump (midjump.com), rebuild

A small static site. There is no framework: one script (`build.js`) reads one data file and writes plain HTML pages into `dist/`, which Cloudflare publishes.

## Map of the repo

```
midjump2/
├── build.js                 ← START HERE. Page templates + the build script
├── src/
│   ├── data/domains.json    ← All 49 domains (names, categories, tiers, logos, text)
│   ├── styles/site.css      ← All the styling (desktop/tablet + phone)
│   ├── js/site.js           ← All the behaviour (menus, filter, marquee, carousel, forms)
│   └── assets/
│       ├── svg/             ← Logos (158 files), navbar logo, Escrow logo
│       └── fonts/           ← Self-hosted fonts (5 files)
├── wrangler.jsonc           ← Cloudflare settings (publishes the dist/ folder)
├── tools/make-data.mjs      ← One-off script that created domains.json (do not re-run)
├── package.json             ← Only defines "npm run build" (= node build.js)
└── dist/                    ← Generated by the build. Not in the repo.
```

## What lives where

| I want to change… | Open… | Look for… |
|---|---|---|
| Landing page text, hero, FAQ answers | `build.js` | `landing`, `FAQ_D` (desktop), `FAQ_M` (phone) |
| Which logos scroll in the landing marquee | `build.js` | `MQ` |
| Navbar links, footer text | `build.js` | `NAV`, `header`, `footer` |
| Contact page text | `build.js` | `contact` |
| Domain page layout or wording | `build.js` | `domainPage` |
| Page titles and descriptions (SEO) | `build.js` | `layout` (shared), `domainPage` (per domain) |
| Sitemap / robots.txt | `build.js` | bottom of the file |
| A domain's text, categories, tier | `src/data/domains.json` | the domain's name |
| A logo's size or position in the gallery | `src/data/domains.json` | `desk` (desktop/tablet) and `phone` |
| Gallery order on phones | `src/data/domains.json` | `order2col` |
| Logo carousel tweaks on a domain page | `src/data/domains.json` | `logoFx` |
| Colours, sizes, spacing, fonts | `src/styles/site.css` | the section comments (`/* ===== gallery … */`) |
| Anything on phones only | `src/styles/site.css` | rules inside `@media (max-width:639px)` |
| How something behaves (filter, drag, forms) | `src/js/site.js` | the comment above each block |
| Contact/inquiry form destination | `build.js` and `src/js/site.js` | `WEB3_KEY`, `data-key`, `Web3Forms` |

Tablets and desktops share one layout. The phone layout switches on under 640px wide.

## How a change reaches the site
1. Edit a file and commit/push to `main` on GitHub.
2. Cloudflare runs `node build.js`, which writes `dist/`, and publishes it.
3. Until the Cloudflare GitHub app is installed, start the build by hand: Deployments → Create deployment (or Retry build).

To preview locally: `node build.js`, then serve `dist/` (for example `python3 -m http.server -d dist`).

## Common jobs
- **Add a domain:** copy an existing entry in `src/data/domains.json`, change the fields, add its logo SVG to `src/assets/svg/`. The gallery, its page, the filter, the sitemap and the "More from the collection" picks all update on the next build.
- **Change a category:** edit the `categories` list on that domain in `domains.json`.
- **Change a URL:** the page folder is the slug (`/domains/<slug>`). Changing a slug breaks the old link, so add a redirect first.

## Good to know
- `domains.json` is now the source of truth. `tools/make-data.mjs` created it from the old repo and would overwrite your edits if re-run.
- The old React site is kept in the private `midjump1` repo for reference.
- Logo SVGs total about 11 MB and still need optimising.
